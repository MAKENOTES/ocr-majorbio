# Recognition 模块指南

## 作用域

本文件仅适用于 `recognition/` 目录，并继承仓库根目录 `AGENTS.md` 的全部规则。若两者存在表述差异，以根目录的全局约束和用户当前明确要求为准。

## 模块概述

本模块实现基于 CRNN/CTC 的文本行识别。图像按固定高度和动态宽度预处理，经卷积与序列模型得到时间步分类结果，再结合 `recognition/keys.txt` 完成 CTC 解码。

## 模块结构

- `models/`：CRNN 及相关骨干网络、序列建模和分类头。
- `components/dataset.py`：训练和推理数据集、动态 padding、bucket batch sampler 及 DataLoader 构建。
- `components/converter.py`：标签编码、CTC target 构建和预测解码。
- `utils/dictionary.py`：字符字典读取和检查。
- `utils/normalization_label.py`：识别标签规范化。
- `train.py`：识别训练入口。
- `inference.py`、`evaluate_val.py`：PyTorch 推理和验证集评估入口。
- `doc/`：模型、数据流、批处理和训练问题记录。
- 根目录 `recognition_export_onnx.py`、`recognition_quantize_static*.py`、`recognition_inference.py`：导出、量化及 ONNX/OpenVINO 推理入口。

## 字典与标签契约

- `keys.txt` 的字符内容和顺序属于模型类别映射契约。不得随意重排、排序、去重、替换或删除字符。
- 修改 `keys.txt` 时必须同步检查类别数、CTC blank 索引、标签转换器、模型分类头、既有 checkpoint 兼容性和所有推理解码入口。旧 checkpoint 通常不能直接复用新的类别映射。
- 标签规范化需明确处理中英文符号、全角半角、空格、下划线和印章干扰。不得为降低错误率而静默删除有效字符。
- 遇到未知字符、空标签或无法编码的样本时，应给出可定位到样本的明确处理或错误信息，不能悄悄映射到其他字符。
- 训练、验证和推理必须使用一致的字符字典及规范化规则，避免离线指标与实际推理含义不同。

## 动态宽度与 CTC 契约

- 图像高度、通道数、宽度缩放策略、最大宽度和归一化方式必须与模型及推理入口一致。
- 动态 padding 只扩展批内画布，不得改变每张图像的有效宽度语义。传入模型的宽度张量必须对应预处理后的实际内容宽度。
- 卷积下采样后的序列长度、有效图像宽度、CTC input length 和 target length 必须一致。修改 stride、padding、backbone 或宽度换算公式时同步检查所有相关入口。
- bucket batch sampler 的分桶和排序只能优化 padding 开销，不得丢样本、重复样本或改变标签与图像的对应关系。
- CTC 解码必须正确处理 blank 和连续重复字符，并保持批量推理输出顺序与输入顺序一致。

## 模型与 checkpoint

- checkpoint 可能保存为纯 `state_dict` 或带 `state_dict` 等字段的字典。修改加载逻辑时保持现有格式兼容，并明确模型结构、类别数和字典版本。
- 修改 `models/` 后同步检查训练、验证、PyTorch 推理、ONNX 导出、量化和 OpenVINO 推理入口的输入及输出契约。
- 不通过 `strict=False` 隐藏类别数、层名或结构不匹配问题，除非任务明确要求部分加载，且代码会报告未加载和意外字段。
- 保存或评估最佳模型时保持指标方向明确，例如 CER 越低越好；不得混用 loss、CER 和 accuracy 的比较方向。

## 修改要求

- 修改数据集、动态 padding 或 batch sampler 时，检查不同宽度、不同批量大小、最后一个不满批次和单样本批次。
- 修改标签转换或规范化时，使用包含中英文符号、空格、下划线、重复字符、未知字符和空标签的代表性样本验证编码与解码。
- 修改模型宽度下采样或 mask 逻辑时，用已知有效宽度的合成批次检查序列长度，避免 padded 区域参与有效预测。
- 训练超参数继续使用 `train.py` 中的常量配置。除非用户明确要求，不新增命令行参数，也不擅自开始长时间训练。

## 导出与量化

- ONNX 导出必须保留推理入口需要的批量和动态宽度轴，并明确图像张量及有效宽度张量的名称、类型和形状。
- 导出后至少检查模型可加载，并用不同有效宽度的输入确认输出时间维和解码路径正常。
- 量化校准数据必须复用正式推理的灰度或颜色通道、resize、padding 和归一化语义。
- 验证导出和量化逻辑时输出到新的临时路径，不覆盖现有 `.onnx`、`.xml`、`.bin` 或 INT8 文件。

## 验证要求

根据改动内容选择最小但有针对性的验证：

- 字典或标签：检查 encode/decode 往返、未知字符、空标签、重复字符及中英文符号。
- 数据或批处理：覆盖不同宽度、批量大小、单样本和不满批次，并核对图像、标签和有效宽度对应关系。
- 模型：使用小型合成张量检查输出形状、有效序列长度、有限损失和反向传播。
- 推理：检查批量结果顺序、CTC blank/重复字符折叠及 CPU 行为；涉及 CUDA 时再补充 GPU 检查。
- 导出或量化：检查产物可加载、动态宽度轴有效，并比较 PyTorch 与目标运行时的输出形状和基本解码一致性。
- 文档或纯配置：至少执行引用检查和 `git diff --check`。

除非用户明确要求并已确认资源，不运行完整训练。缺少数据集、checkpoint、CUDA 或目标运行时时，应报告对应验证未执行及原因。
