# 分级 AGENTS.md 初始化设计

## 目标

为 OCR 仓库建立可直接指导编码代理工作的分级说明，继承 `context.txt` 中的既有约束，并补充仓库结构、开发流程、验证要求和大文件保护规则。

## 文件结构

创建三个作用域明确的说明文件：

- `/AGENTS.md`：适用于整个仓库，记录语言、环境、依赖、代码风格、配置方式、验证和文件保护等全局规则。
- `/detection/AGENTS.md`：补充文本检测模块的目录职责、训练与推理入口、数据格式、模型导出和针对性验证要求。
- `/recognition/AGENTS.md`：补充文本识别模块的目录职责、训练与推理入口、字典及标签处理、动态宽度批处理、模型导出和针对性验证要求。

子目录说明只记录模块特有内容，并明确继承根目录规则，避免重复和冲突。

## 根目录规则

根目录说明包含以下内容：

1. 项目是基于 Python、PyTorch 的 OCR 工程，流程分为文本检测和文本识别，并包含 ONNX、OpenVINO 与 INT8 量化工具。
2. 所有回复使用中文；新增代码注释和函数文档使用中文。函数和参数采用完整 docstring 说明，避免用零散单行注释代替接口文档。
3. 所有 Python 命令和依赖安装必须在项目虚拟环境中执行；依赖变化同步更新 `requirements.txt` 和相关说明。
4. 训练脚本和工具的配置沿用仓库现状，使用文件内常量，不新增命令行参数，除非用户明确要求改变该约定。
5. 从仓库根目录运行脚本，避免相对导入和相对路径行为变化。
6. 涉及检测核心流程时创建或更新 `ocr_detection_plan_current.md`，记录目标、关键决策、验证结果和后续事项。
7. 不提交或覆盖数据集、checkpoint、运行日志及生成模型；修改导出或量化逻辑时使用新的临时输出路径。
8. 验证应与改动风险匹配：优先运行现有测试；没有对应测试时至少执行语法编译或导入检查，并对入口脚本进行最小可行验证。不得为验证启动完整训练任务。

## 检测模块规则

检测说明介绍 EAST 检测流水线及以下边界：

- `models/` 负责网络结构，`components/` 负责数据、变换、标签图、损失和评估指标。
- 当前主要训练脚本包括 ResNet 和 MobileNet 变体；修改时保持所选模型、数据变换、checkpoint 加载及导出脚本一致。
- 标注由图像和对应文本标签组成，数据读取或几何变换必须保持四边形坐标、score map 和 geometry map 对齐。
- 损失、后处理或缩放逻辑的改动需要覆盖空标注、退化多边形、不同图像尺寸以及 CPU/GPU 设备行为。
- 导出或量化后至少检查模型可加载、输入输出名称与形状符合推理脚本预期。

## 识别模块规则

识别说明介绍 CRNN/CTC 流水线及以下边界：

- `models/` 负责识别网络，`components/` 负责数据集、动态 padding、批采样和标签转换，`utils/` 负责字典与标签规范化。
- `recognition/keys.txt` 的字符顺序属于模型契约；不得随意重排、去重或替换，变更时必须同步检查类别数、checkpoint 兼容性和解码结果。
- 标签规范化需关注中英文符号、空格、下划线和印章干扰，不得静默丢弃未知字符。
- 动态宽度输入的图像宽度、序列长度和 CTC target length 必须保持一致，相关改动需覆盖不同宽度和批量大小。
- 导出或量化后至少验证模型可加载、动态宽度轴和解码输出符合推理脚本预期。

## 错误处理与验证

说明文件不改变运行时行为。代理执行后续任务时，应先确认虚拟环境、数据和模型路径存在，再运行昂贵命令；缺少本地资产时报告未执行项，不伪造结果。验证失败时保留原始错误并定位根因，不通过降低断言或吞掉异常规避问题。

## 验收标准

- 三个 `AGENTS.md` 均存在，Markdown 结构清晰。
- 根目录规则与 `context.txt` 一致，没有相反要求。
- 两个模块文件只增加各自作用域规则，并能指向真实存在的目录和脚本。
- 文档不包含占位符、无法执行的虚构命令或对缺失数据和模型的假设。
- `git diff --check` 通过。
